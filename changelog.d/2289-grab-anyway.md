### Fixed
- **Grab anyway for a release Bindery already imported** (#2289). When a release was marked imported but that import left nothing usable, every Grab answered "already grabbed: this release has already been imported", and the only ways out were deleting the book or deleting the torrent in your download client, which on a ratio tracked tracker throws away its seeding history. Grab now asks whether to grab it anyway, on the Search page, a book's search results and the Wanted page. Confirming sends the release to your download client again and reuses the old Queue entry. Nothing is removed from the download client and the grab does not touch the files the book already has. It is for an import whose files are missing: while they are still there, the new download is skipped as a duplicate. A release that is still downloading or importing is refused as before. API callers send the grab again with `"force": true`. Thanks to schmitzkr for the report and Terebi42 for confirming it.
