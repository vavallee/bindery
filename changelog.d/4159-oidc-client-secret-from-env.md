### Added

- **OIDC client secrets can come from the environment** (#4159). Set `BINDERY_OIDC_<ID>_CLIENT_SECRET` (for example `BINDERY_OIDC_KEYCLOAK_CLIENT_SECRET` for a provider with id `keycloak`) and Bindery uses it instead of the stored secret. Saving a provider no longer writes a secret for it, and the provider form shows the field as set via environment variable with the variable name. A secret you stored earlier stays in the database and backups until you delete and re-add the provider. Provider ids that would share one variable, such as `my-idp` and `my_idp`, can no longer be saved together. Works with Docker and Kubernetes secrets and other secret injectors. Thanks to GianniBYoung for the request.
