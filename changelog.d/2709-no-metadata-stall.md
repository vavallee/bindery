### Fixed
- **A magnet that never gets its metadata is now failed instead of sitting in the queue for ever** (#2709): a torrent your client accepted but never resolved has no file list, no size and no progress, and none of the clients call that an error, so it stayed at "downloading" indefinitely. One reporter's had been there 34 days. Once such a torrent is older than the stall timeout (2 hours by default) Bindery now removes it from the client, fails the queue row with "the download client never resolved this magnet's metadata" and searches again. Covers Transmission, qBittorrent, Deluge and rTorrent. Unlike other stalls the release is **not** blocklisted, because a magnet with no metadata usually says more about your connection than about the release, and if most of the unfinished torrents in a client look that way Bindery blames the client, logs it and leaves them all alone rather than failing the lot. Nothing is judged before the timeout, because a healthy magnet looks exactly the same while it resolves. Thanks to ccarpinteri for the report and the diagnosis.
