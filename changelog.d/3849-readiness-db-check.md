### Added
- **Readiness endpoint that checks the database** (#3849). `GET /api/v1/health/ready` answers 503 when Bindery's database connection is closed or unusable or the driver returns an error, and 200 otherwise, with no credentials needed. A database that is only busy with a long scan, import or VACUUM still counts as ready, so those jobs never take Bindery offline. The Helm chart's readiness probe now uses it. Liveness and the Docker healthcheck stay on the static `/api/v1/health`, so a slow disk never triggers a restart.
