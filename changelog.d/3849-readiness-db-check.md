### Added
- **Readiness endpoint that checks the database** (#3849). `GET /api/v1/health/ready` answers 200 when the database responds within about two seconds and 503 when it does not, with no credentials needed. The Helm chart's readiness probe now uses it, so a pod with a stuck database drops out of the Service instead of taking traffic it cannot serve. Liveness and the Docker healthcheck stay on the static `/api/v1/health`, so a slow disk never triggers a restart.
