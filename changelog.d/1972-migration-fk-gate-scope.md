### Fixed
- **Bindery would not start after upgrading to v1.30.1–v1.30.3** (#1972) — the instance exited on every restart with `migration 72: foreign_key_check found N violation(s)`. Migration 72's integrity check scanned the entire database instead of the two Calibre tables it rebuilt, so orphan rows left over from the pre-#1727 foreign-key drift — accumulated long before that migration existed — aborted the upgrade. Longer-running instances were the most likely to hit it. A migration is now gated only on violations it introduces itself; pre-existing ones are logged with their table names and counts and no longer stop the instance. Nobody lost data: the migration ran in a transaction and rolled back each time.

### Added
- **`bindery db-check` and `bindery db-repair`** (#1972) — offline database integrity tooling that runs without applying migrations, so it works on an instance that can't start. `db-check` lists every row whose foreign key points at a missing parent and changes nothing; `db-repair --yes` replays the delete rule the schema declares (`ON DELETE CASCADE` rows removed, `ON DELETE SET NULL` references cleared) and reports what it did. Also reachable as `BINDERY_DB_FK_CHECK=report|repair` where the container command can't be edited. See [Troubleshooting](docs/Troubleshooting-Wiki.md).
