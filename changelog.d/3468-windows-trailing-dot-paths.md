### Fixed
- **Windows: a folder ending in a dot, or with other capitals, no longer shows as a new file** (#3468). On Windows a book titled `H.R.H.` was moved into a folder Windows quietly renamed to `H.R.H`, and a move into an existing folder kept that folder's own capitals. The stored path still opened, but the next library scan counted one file fewer as tracked and listed the same file as unmatched. Bindery now leaves off the trailing dots and spaces Windows would drop when it builds a folder or file name, and the scan and the reorganize preview treat paths that differ only by capitals or a trailing dot as the same file on Windows. Libraries already stored this way need nothing rewritten, the next scan simply recognises them. Linux and macOS paths are unchanged. Thanks to kennethp1015 for the detailed trace.
