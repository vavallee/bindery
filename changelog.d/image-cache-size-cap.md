### Fixed
- **The cover cache now has a size limit.** Cached covers were only ever removed by age (30 days), so nothing stopped the cache from growing until it filled the config volume, which is the same volume the database lives on. It now stops at 2 GiB by default, counted the way the disk sees it (whole 4 KiB blocks per file). When it fills up, the oldest covers are removed to make room, and until that sweep has run covers are still fetched and shown as usual, just not saved. The sweep also runs shortly after startup now, where it used to wait a full day. A cache already over the limit when you upgrade is trimmed down to it. Most libraries are nowhere near the limit and will see no change. Set `BINDERY_IMAGE_CACHE_MAX_MB` to raise or lower it. `GET /api/v1/system/status` reports the limit as `imageCacheMaxBytes` next to `imageCacheBytes`.
