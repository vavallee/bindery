### Fixed
- **qBittorrent behind a reverse proxy can log in again** (#3668). Bindery's login sent `Origin` and `Referer` headers that qBittorrent's CSRF check compares with the host it receives, so a seedbox or any other proxied qBittorrent turned the login away with `HTTP 401: Unauthorized` while the *arr apps connected fine with the same settings. The login now sends neither header, like those clients, the base URL leaves out a default port (443 for https, 80 for http) so the `Host` header matches what a proxy expects, and a remaining 401 explains that it comes from a proxy login or qBittorrent's Host header validation, not the username and password. Thanks Duckburg-Net for the report and NopeCharon for the fix.
