### Fixed
- **A usenet download that holds only a .zip is no longer reported as "no book files found"** (#4131). SABnzbd and NZBGet unpack RAR and 7z but leave a zip alone, and scene ebook releases, German ones especially, are often a zip that holds a rar that holds the EPUB. A `.zip` or `.7z` is now recognised as an archive like a `.rar`: the Queue says the download is waiting for it to be extracted, names the archive type, spends no import retries, and keeps the archive out of the library. Thanks to @BraynArts for the report and the clear writeup.

### Added
- **Bindery unpacks the .zip of a usenet download itself** (#4131). Switch it off with **Extract ZIP archives of usenet downloads** (`import.extract_zip`, Settings, File Naming, on by default). It needs no external tool, and it is strict: only SABnzbd and NZBGet downloads, only inside Bindery's own download folders (a path the client reports anywhere else is never written to), only when no book file is there yet, and one level only, so a RAR that comes out of the zip still waits for an unpacker. It refuses a zip with an unsafe entry name, more than 2000 entries, more than 4 GiB unpacked or a compression ratio above 100 to 1, skips password protected entries and links, never overwrites a file, and removes what it wrote if it fails. RAR and 7z are still not unpacked by Bindery.
