### Added
- **Bindery unpacks the .zip of a usenet download itself** (#4131). SABnzbd and NZBGet leave a zip alone, and scene ebook releases, German ones especially, are often a zip that holds the book. Bindery now extracts it in place and imports the book, with no external tool. It is on by default and can be switched off with **Extract ZIP archives of usenet downloads** (`import.extract_zip`, Settings, File Naming); when it is off, the download waits for an unpacker as before. It is strict: only SABnzbd and NZBGet downloads, never a torrent, a Soulseek folder or a manual import, only inside Bindery's own download folders (`BINDERY_DOWNLOAD_DIR`, `BINDERY_AUDIOBOOK_DOWNLOAD_DIR` and the client's path remap), only when no book file is there yet, and one level only, so a zip inside the zip is left alone. That folder must be writable by Bindery. A zip is refused whole, with the reason in the Queue, when an entry name is unsafe, longer than 1024 bytes, over 255 bytes in one path segment or deeper than 32 levels, it holds more than 2000 entries or would create more than 2000 folders, its directory is larger than about 2.6 MB, it unpacks to more than 4 GiB in total or 2 GiB for one file, or it compresses more than 100 to 1. A zip that holds nothing that looks like a book is undone and says so. Password protected entries, links and special files are skipped, a file that is already there is never overwritten, and a failed or stopped extraction removes what it wrote. The zip stays in the folder until the usual cleanup: in move mode (and hardlink mode, which moves usenet files) a fully imported job folder is removed with it, in copy mode it stays with the client's job. RAR and 7z are still not unpacked by Bindery. Thanks to @BraynArts for the report.
